# 業務画面の動作確認

更新：2026-11-12。最新保存価格と収集実行履歴を確認する1ページ。市場一覧→選択市場詳細→補助的な稼働情報の順で表示する。画面の取得はDB参照のみで、外部API収集・保存を開始しない。

## 起動する順序

1. Docker Desktopを起動する。
2. プロジェクトルートで次を実行し、mysqlがhealthyになることを確認する。

```powershell
docker compose up -d --wait
docker compose ps
```

3. IntelliJでbackendのCryptoMarketMonitorApplicationを実行する。起動完了ログを確認する。通常設定では起動時回収の後に定期収集が始まる。同じDBに対するBootは1プロセスとする。
4. VS Codeでfrontendを開く。統合PowerShellで以下を実行する。

```powershell
npm.cmd ci
npm.cmd run dev
```

依存が変わっていなければciは毎回不要。初回やpackage-lock.json変更時に実行する。Nodeの対応範囲はpackage.jsonを正本とし、今回の検証版は24.18.0。PowerShellのままnpm.cmdを使えばnpm.ps1の実行制限を回避できる。

5. ブラウザで <http://127.0.0.1:5173/> を開く。

## 画面と通信の確認

初回表示・表示更新ボタン・30秒周期で以下を並行取得する。Networkで3 GETを確認できる。収集APIではなくDB参照であり、Springの60秒収集周期や外部API頻度は変更しない。

- GET `/api/v1/quotes/latest`
- GET `/api/v1/collection-runs?limit=100`
- GET `/api/v1/quotes/history?exchange=COINBASE_EXCHANGE&symbol=BTC-USD`

1. ヘッダーの目的・対応1市場・現在の収集対象を確認。市場一覧はCoinbase BTC-USDと拡張候補Coinbase ETH-USD/Kraken BTC-USDの計3件。候補の数値は「—」。行全体を選択すると未収集案内となり、候補へのAPIは呼ばれない。実市場へ戻ると保持した指標・履歴ページを復元する。実市場のMid/Spreadは詳細と一致することを確認。
2. 価格推移のMid/スプレッドを切り替える。点をクリック/タップしJST日時と価格を確認。3分超の欠測は線が途切れ、0件は空表示、1件は点表示となる。
3. 平均/最大/最小スプレッドと検索期間・対象観測件数を確認。サーバーで期間全体を集計する。系列の上限2000件に達したら、グラフだけ一部である注意が出る。
4. 収集状況の成功率は取得済み最大100件のうちRUNNINGを除いた終了済み件数が分母。SKIPPED/INTERRUPTEDも分母へ含む。終了済み0件は「—」。全期間の成功率ではない。
5. 履歴は初期状態で閉じている。「収集実行履歴を開く」で5件、「履歴を詳しく見る」で10件ページ送り。「最新5件に戻る」で5件へ戻る。外側を閉じても自動更新で勝手に開かず、閲覧ページ/チャート指標を保持する。
6. 30秒後に3 APIが再取得され、処理中は更新ボタンが無効になることを確認。正常時のAPI取得時刻は非表示で、観測時刻/経過は保持。部分失敗時は前回値/取得成功時刻とエラーを残す。

金額は文字列から十進計算し、表示のために有効桁を丸めない。平均スプレッドの表示だけ小数4桁へ四捨五入（正の0.0001未満は閾値表示、元値はtitle）、率は小数6桁で四捨五入し、微小な正値は「0.000001%未満」。グラフ座標だけnumberへ変換する。統計はサーバーから受信した値を表示し、グラフ点だけから平均を作り直さない。

鮮度は1秒時計で端末時刻との差を進め、3分以上で注意。未来の観測は時計不整合を表示する。表示更新日時・観測日時・検索期間を区別する。履歴のFAILEDは収集結果であり、画面HTTP失敗ではない。

## 起動に失敗した場合

- Bootの`Communications link failure` / `Read timed out`：MySQLとの通信失敗。まずcompose psでhealthyを確認し、DB接続先とポート、MySQL/Bootログを確認する。FlywayやDB制約を無効化して回避しない。
- APIが404：正しいbackendプロジェクトの最新クラスで起動しているか確認する。
- Viteだけ表示できる：Bootが起動できたことを意味しない。画面エラーとBootログを確認する。
- DB認証失敗：既存volumeの資格情報と.envが一致するか確認する。.envを書き換えても既存DBのパスワードは変更されない。

復旧のためにvolumeの削除・DB初期化は行わない。通常の停止はVite→Boot→MySQLの順とし、[ローカル起動手順](../04_開発環境/ローカル起動手順.md)を参照する。

## 閲覧UIの最終確認

- PC/375pxで縦並び・ページスクロール。市場は3件、対応は1件だけ。スマートフォンでは市場行は2行、Bid/Askは横並び、統計は項目と値が横並び。
- 数量と「このアプリについて」は初期折りたたみ。開くと必要な補足が確認できる。
- 通常の収集補足は直近結果/成功率/観測経過だけ。履歴を開くと処理時間と失敗理由まで確認できる。
- 平均が4桁へ丸まり、hoverでは元値を確認できる。チャートデータやAPI精度は変わらない。
- 長い欠測がある場合だけ短い注記を表示。3分超の線の欠測表現は既存仕様を維持。
- GitHub URLは本番Dockerビルドで実リポジトリを設定する。GitHub/READMEへのリンク先を確認する。未設定・不正URL時に架空リンクを出さないことは部品試験で確認する。
