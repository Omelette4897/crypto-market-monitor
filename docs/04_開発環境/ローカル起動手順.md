# ローカル起動手順

## 現在地・役割

要件定義・基本設計→開発環境→収集/保存/API→定期実行（実装済み）→業務画面→結合確認・公開。
以下は環境を起動する手順です。2026-11-08の機能D追加後はバックエンド起動時に実Coinbaseから自動収集します。設定と確認は[定期実行の動作確認](../05_テスト/定期実行の動作確認.md)を参照してください。

アシスタントがファイル・依存・設定を用意し、利用者は以下を実行して起動と停止を確認します。コマンドはWindows PowerShell用です。画面に表示されるログを見ながら操作してください。

## 1. プロジェクトのフォルダへ移動

```powershell
cd 'C:\path\to\crypto-market-monitor'
```

`C:\path\to\crypto-market-monitor`は例示パスです。実際に配置したプロジェクトルートへ読み替えてください。

このフォルダにcompose.yaml、backend、frontend、scriptsがあります。

## 2. ローカル設定を準備

```powershell
node .\scripts\init-local-env.mjs
```

.envを生成し、アプリ用とDB管理用で異なるランダムパスワードを設定します。既存の.envは上書きしません。既に生成済みでも再実行できます。パスワードは画面・Git・チャットへ貼らないでください。
.env.exampleは項目の説明用です。実際の.envはGit管理しません。環境変数に同名のDB_PASSWORD等が既に設定されている場合はそちらが優先されるため、異なる値がある場合は確認します。

## 3. MySQLを起動（PowerShell A）

Docker Desktopを起動してから実行します。

```powershell
docker compose up -d --wait
docker compose ps
```

mysqlがhealthyになればDB起動完了。Aは起動完了後、別の操作にも使えます。
MySQLデータはvolumeに保持します。停止・コンテナ再作成で同じDBを使います。初期化済みDBのパスワードは.envを書き換えただけでは変更されません。エラー時はvolumeを消さず、ログを確認します。

## 4. Spring Bootを起動（PowerShell B）

新しいPowerShellを開き、次を実行します。

```powershell
cd 'C:\path\to\crypto-market-monitor\backend'
.\mvnw.cmd spring-boot:run
```

Maven Wrapperが必要なMavenと依存を取得します。初回にはインターネット接続が必要です。JavaはJAVA_HOMEのJDK 21を使います。
ローカルプロファイルが親フォルダの.envを読みます。Flywayが業務テーブルを作成/検証し、JPAが対応を検証します。Bootが127.0.0.1:8080で待ち受け、起動時回収のコミット後、自動収集を開始します。回収に失敗すると起動を失敗させます。`COLLECTION_ENABLED=false`なら回収だけ行い、収集は開始しません。
このPowerShellは開いたままにします。サーバーが起動している間は通常の入力待ち表示へ戻りません。

## 5. Vueを起動（PowerShell C）

```powershell
cd 'C:\path\to\crypto-market-monitor\frontend'
npm.cmd ci
npm.cmd run dev
```

Viteが127.0.0.1:5173で待ち受けます。Cも開いたままにします。npm.cmdはPowerShellのスクリプト実行ポリシーによるnpm.ps1の制限を避けるための通常のWindows用コマンドです。

## 6. ブラウザで確認

<http://127.0.0.1:5173/> を開きます。初回に最新保存価格と収集実行履歴を取得します。「表示更新」は保存済みデータを再取得し、Coinbase収集やDB登録を開始しません。

- 最新保存価格のBid/Ask・数量・観測日時と、収集実行履歴を表示。
- 0件は正常な空表示、接続失敗はエラー表示として区別。
- 表示更新日時は端末でAPI取得に成功した時刻。価格の観測日時とは別。
- 各領域の失敗は独立して表示し、更新失敗時は前回値を残す。

詳細とテスト実行は[業務画面の動作確認](../05_テスト/業務画面の動作確認.md)を参照してください。任意の健康確認は`http://127.0.0.1:8080/actuator/health`。通常の画面取得に健康確認は挟みません。

## 7. 停止と再起動

1. CでCtrl+Cを押してViteを停止。
2. BでCtrl+Cを押してSpring Bootを停止。.cmdの終了確認が出たら確認して終了。
3. AでプロジェクトルートからDBを停止。

```powershell
docker compose down
```

このコマンドはDBデータvolumeを削除しません。再起動は手順3→4→5です。依存が変わらなければ、毎回npm ciをやり直す必要はありません。

## エラーの切り分け

| 状況 | 確認 |
|---|---|
| Dockerへ接続不可 | Docker Desktopの起動とdocker versionのServer表示 |
| 3306使用中 | 他のDBを停止できるか確認。勝手にプロセスを終了しない。必要ならDB_PORTを調整 |
| 8080/5173使用中 | 前回のアプリが動いていないか確認。別アプリは勝手に停止しない |
| Communications link failure / Read timed out | compose psでmysqlがhealthyか、DBの接続先/ポートとBootログを確認。Flywayを無効化して回避しない |
| DB認証エラー | .envと初期化済みvolumeの資格情報が一致するか確認 |
| 画面は開くが接続失敗 | DB→Bootの順で起動、8080のhealth、Bootログを確認 |
| Maven初回取得に失敗 | インターネット・プロキシ・JAVA_HOMEを確認 |

公開用ではありません。各ポートは127.0.0.1へ限定しています。クラウドの公開設定は後続工程で作成します。

## GitHub / READMEへの画面リンク（公開URL確定後）

frontend/.env.exampleを参考にfrontend/.env.localを作り、`VITE_GITHUB_REPOSITORY_URL`へ実在するHTTPSのGitHubリポジトリURLを設定する。未設定ならリンクは表示しない。READMEはそのURLの`#readme`へ移動するため、ブランチ名を推測しない。Viteを再起動（本番は再ビルド）すると反映される。VITE_で始まる値はブラウザへ公開されるため、トークンやパスワードを設定しない。.env.localは既存.gitignoreで除外される。
