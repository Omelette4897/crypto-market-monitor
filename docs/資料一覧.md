## 工程別の配置と判断基準

資料は主な用途により1か所へ置き、他工程からはリンクで参照する。番号は表示順であり、工程の完了を意味しない。開発中の設計変更やテスト結果に応じ、該当資料を更新する。

| フォルダ | 判断すること・収録資料 |
|---|---|
| 01_要件定義 | 何を実現するか。目的・範囲・機能/非機能要件 |
| 02_基本設計 | 外部から見た仕様と全体構成。基本設計、API契約。DB構造は基本設計内で管理 |
| 03_詳細設計 | どう実装するか。機能A〜Eの処理・クラス・状態管理とJavaパッケージ構成 |
| 04_開発環境 | 実装・検証を行う環境。ローカル起動、IDE操作 |
| 05_テスト | 試験の実行・動作確認手順。API・定期実行・画面・実Coinbase・DB統合テスト |
| 06_リリース・運用 | Railway Hobbyの構成・手動デプロイ・費用/停止/解約。初回公開済み、運用確認は継続中 |

個別テストケースの仕様はテストソースを正本とし、05_テストへ別仕様書として複製しない。Git/CI、ST/UAT、リリース、運用の資料は必要な工程で追加する。フォルダを埋めるためだけの資料は作らない。

各工程の現行仕様・実行手順・検証記録への入口を以下にまとめる。
