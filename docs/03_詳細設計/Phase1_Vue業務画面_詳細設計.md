## 1. 目的・既存との関係

既存のVue接続確認ページを、最新保存価格と収集実行履歴を確認する業務画面へ置き換える。バックエンドの2 GETとDB契約は変更しない。通常の画面取得にActuatorの接続確認を必須条件として挟まない。実データの参照API自身の結果で表示状態を決める。

初期対象はCoinbase Exchange / BTC-USD。最新価格はAPIのitems配列を扱い、先頭1件だけを取り出す設計にしない。画面からCoinbase取得やDB保存を開始しない。

## 2. 合意済みの画面動作

- 最新価格：市場/ペア、Bid/AskとUSD単位、各数量とBTC単位、観測日時、領域別の表示更新日時。
- 履歴：実行ID、開始/終了日時、状態、理由。中断検出日時は理由欄へ補足し、終了時刻と混同しない。
- 初回表示と表示更新で2 APIを並行取得。処理中はボタンを無効化。全体の取得が終わる前でも成功した領域は更新する。
- 一方の失敗で他方を隠さない。初回取得失敗と正常0件を区別する。更新失敗は前回値/前回成功日時を保持し、正常0件なら前回値を消す。
- 収集履歴のFAILEDは取得成功した業務データであり、画面のHTTP失敗ではない。
- 価格・数量・IDは文字列を維持し、丸めやNumber変換をしない。価格・数量は文字列のまま3桁区切りと小数末尾ゼロ除去を行う。IDは桁区切りしない。日時はJST、任意値nullは「—」。
- API取得成功時点で観測から3分以上なら注意表示する。価格は残す。再判定は次のAPI取得成功時。タイマーで判定だけを進める処理も自動API再読込も追加しない。
- 3分は暫定的な画面注意の基準。端末時刻と受信観測時刻の差を使い、市場データの真の鮮度・裁定判断の可否を保証しない。
- 履歴は新しい順の最新100件を取得し、10件ずつ画面内でページ送りする。DB全履歴のページ検索ではない。自動再読込・グラフ・検索・収集実行ボタンは追加しない。

## 4. 呼出し・状態設計【合意済み・実装済み】

```text
App.vue：初回表示 / 表示更新
  → useMarketMonitor.refreshMarketData()
      ├ fetchLatestQuotes() → 最新価格の状態を独立更新
      └ fetchCollectionRuns() → 履歴の状態を独立更新
  → propsで各Panelへ渡す → Vueが状態変更を画面へ反映
```

latestQuotesStateとcollectionRunsStateの両領域に以下を保持する。

| 状態 | 意味 |
|---|---|
| items | 最後に正常取得した配列。初期値は空配列 |
| isLoading | 今回の取得中か |
| errorMessage | 直近取得の画面向けエラー。正常時はnull |
| lastSucceededAt | 最後の正常応答を確認した端末時刻。初期値null |

lastSucceededAt=nullとitems空の組合せで「まだ成功していない」を区別する。正常0件でもlastSucceededAtは更新する。古い価格の判定基準には最新価格領域のlastSucceededAtを使い、再取得失敗時には観測/成功日時/注意判定を保持する。

全体のisRefreshingは2領域のisLoadingのORから導出し、ボタン無効化と関数側の二重実行防止に使う。一方の例外を独立して処理し、他方の成功を捨てない。

### 9.1 画面・状態

ヘッダー→市場概要→24時間チャート→収集状況→コンパクトな収集履歴の順。既存の配色とカードを維持し、PC/スマートフォンへ対応する。

- 市場概要：取引所/通貨ペア、Mid、Bid/Askと数量、スプレッド金額/率、観測日時と経過時間。
- ヘッダーの最終全体更新は3 APIがすべて成功した時刻。部分失敗を明示し、各領域の最終成功時刻も表示する。
- 履歴は初期5件。詳細展開後は取得済み100件を10件ずつ表示。自動更新で展開状態・閲覧ページを失わせず、件数減少時は有効なページへ調整する。
- 成功率は取得済み最大100件のSUCCESS数÷終了済み件数。RUNNINGは分母から除外し、FAILED/SKIPPED/INTERRUPTEDは含む。対象・除外件数を表示し、終了済み0件は「—」。全期間の成功率ではない。
- 直近の状態/理由・処理時間も表示。未完了/中断を架空の終了時刻で補わない。
- 鮮度は画面の1秒時計で経過を進め、3分以上で注意。端末より未来の観測は時計不整合を表示する。画面の経過表示更新は外部API取得を起動しない。

### 9.2 読み取り専用の価格履歴・分析API

GET /api/v1/quotes/history。exchange/symbolは任意で、省略時はCOINBASE_EXCHANGE/BTC-USDの1市場を対象にする。既存APIの「省略＝絞り込みなし」は変更しない。空文字・未対応値は400。期間・件数は初期版の固定仕様とし、任意期間やlimitの入力UIは追加しない。

- サーバー時刻を1回取得してrangeEndとし、rangeStart=24時間前。範囲は[rangeStart, rangeEnd)。
- 観測一覧は期間内の最新2,000件を選び、observedAt昇順・同時刻id昇順で返す。追加1件の存在を調べ、truncatedで一覧省略を知らせる。
- 各観測はid・exchange・symbol・observedAt・bidPrice・askPrice・spreadを返す。spreadはSpring BootでAsk−Bidを算出。ID/金額は文字列、時刻はUTC。既存DTOは変更しない。
- 同じAPIでrangeStart/rangeEndとスプレッド統計（観測件数・平均・最大・最小）も返す。集計は2,000件へ制限する前の、対象市場・期間内の全保存観測が対象。
- 一覧検索と集計検索を同じ読み取り専用Txで実行し、期間・市場条件を揃える。Repositoryで件数/合計/最大/最小を集計し、JavaのBigDecimalで平均を算出する。全件をJavaへ読み込んで集計しない。
- 平均は観測ごとの単純平均。時間加重/数量加重ではない。平均は小数16桁・HALF_UP。各spreadと最大/最小は保存小数の精度を維持する。
- 0件は200・items空配列・件数0・統計値null。1件は平均/最大/最小がその観測の値。エラーは既存の400/503/500契約を再利用し、失敗を空配列で隠さない。
- 一覧が省略されても統計を期間全体として表示し、グラフだけ一部であることを明記。失敗した収集・欠測時間の価格を補完しない。既存検索と同様SUCCESS条件は追加しない。

現行DDLには観測時刻/市場検索用索引がない。今回の制約に従いDB/Flywayは変更しない。返却上限はDBの走査量上限ではないため、実MySQLで検索・集計を検証し、大量蓄積時の性能・索引追加を後続の評価事項として残す。

### 9.3 計算・チャート

Chart.jsを直接使用し、Vueラッパーは追加しない。折れ線に必要な部品だけ登録する。横軸は実観測の時刻差を数値軸で表し、Intl.DateTimeFormatでJST表示する。バージョンは実装時に公式の互換性/利用条件・依存監査を確認して固定する。

チャートはMid/スプレッドの切り替え式。スプレッド系列・統計はサーバー応答を表示する。MidはBid/AskからVue側で計算する。0件は空表示、1件は点、観測間隔が3分を超える区間は線を切る。平滑化/価格の補間点は追加しない。統計カードには期間全体の平均/最大/最小スプレッド・対象件数を表示する。

Mid=(Bid+Ask)/2、Spread=Ask−Bid、Spread Rate=Spread/Mid×100。フロントの現在値計算にはdecimal.jsを採用し、設定を分離した有効数字50桁で計算する。計算と書式を分け、金額/数量の有効桁は維持する。率のみ小数6桁で四捨五入し、正の非ゼロ値が表示上0になる場合は「0.000001%未満」。不正値/非有限/0以下の価格/Ask<Bidは計算結果を出さず警告する。描画座標だけnumberへ変換し、ツールチップは元精度のMid/サーバーのspreadを使用する。

Chart.jsとEChartsの比較では、今回の単一折れ線に必要な機能と依存を絞りやすいChart.jsを採用。decimal.jsは既存BigInt減算を割算/丸めまで独自拡張する負担を避けるため採用する。

参考：[Chart.jsの統合](https://www.chartjs.org/docs/latest/getting-started/integration.html)、[Chart.js利用条件](https://www.chartjs.org/docs/)、[EChartsの部分取り込み](https://echarts.apache.org/handbook/en/basics/import/)、[decimal.js](https://mikemcl.github.io/decimal.js/)。
