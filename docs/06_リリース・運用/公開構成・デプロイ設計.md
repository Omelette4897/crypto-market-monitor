# 公開構成・デプロイ設計

更新：2026-11-14。Railway Hobbyで初回構築・公開済み。本番ST/UATと運用確認は継続中。[操作手順](Railwayデプロイ・運用手順.md)、[ST/UAT](../05_テスト/本番配信・ST_UAT確認.md)を参照。

## 配置と責務

```text
開発：ブラウザ → Vite → Spring Boot → Compose MySQL 8.4.13
本番：ブラウザ → Railway提供HTTPS → App（1インスタンス）
                                     ├ Vue静的配信 / 既存REST API
                                     ├ 起動時回復 / 定期収集 → Coinbase
                                     └ private接続 → MySQL 8.4.13 → 永続Volume
```

VueとAPIは同一オリジン。DBだけにVolumeを付ける。Nginx、独自ドメイン、CD、自動スケールは導入しない。DBは同じProject/環境のprivate接続を使い、外部TCP Proxyを作らない。[MySQL](https://docs.railway.com/databases/mysql)、[private networking](https://docs.railway.com/networking/private-networking)

DockerfileはVueビルド→Javaビルド・試験→JRE実行用の3段階。`web-bundle` Maven profileだけが`target/frontend-dist`をJARのstaticへ取り込む。通常の開発・DB試験コマンドは維持する。実行イメージは非rootで、Node/Maven/ソース/.env/鍵を含めない。ベースはメジャー版タグでありパッチ更新を受ける。digest固定による完全な同一バイナリ再現ではない。

`prod`は必須DB変数とRailwayの`PORT`を使い、`0.0.0.0`で待ち受ける。localの.envは読み込まない。DB起動待ちをFlywayで有限回再試行し、失敗時は起動失敗とする。業務処理/API/DB構造は変更しない。[Boot静的配信](https://docs.spring.io/spring-boot/3.5/reference/web/servlet.html)

## 起動・更新・終了

- App/DB各1インスタンス。AppのSleep、自動デプロイ、PR環境を無効にする。
- **旧Appの停止完了後に新Appを手動デプロイする。** 同じDBへ別Appを同時接続しない。短い公開停止を許容する。
- Railway既定の新旧並行切替では、新Appの起動時回復が旧Appの実行中RUNNINGを回収し得る。replica=1やoverlap=0だけでは新旧重複を防げない。収集無効でも回復は走る。
- healthcheckは`/actuator/health`。起動時DB接続確認に使うが、継続監視・Coinbase疎通・収集成功は保証しない。
- SIGTERM猶予90秒。HTTP終了待機と既存収集の最大30秒待機は別段階。収集のキャンセル→待機→割り込み要求を維持し、SIGKILL時は次回起動で回復する。

[Railway終了処理](https://docs.railway.com/deployments/deployment-teardown)、[healthcheck](https://docs.railway.com/deployments/healthchecks)、[Boot graceful shutdown](https://docs.spring.io/spring-boot/3.5/reference/web/graceful-shutdown.html)

## 費用とデータ

Hobbyは月額$5に$5分の利用量を含む。利用量$7なら基本料込み$7が基本となり、税等は別。目標$10〜20、Compute通知$15/Hard Limit $25を設定する。RAMは$10/GB月、CPU・保存・通信も加算されるので目標内は保証しない。[公式料金](https://docs.railway.com/pricing/plans)

上限到達はWorkspaceの停止を伴う。請求総額を厳密に$25以内と保証せずBilling/Usageを確認する。App/DB各1GB・1vCPUを初期上限案とし、OOMと実使用量を確認する。上限は予約使用量ではない。Railway Agentは使わない。[費用制御](https://docs.railway.com/pricing/cost-control)

DB Volumeは`/var/lib/mysql`。Hobby初期容量5GB、履歴自動削除は追加しない。容量増加を監視し、保持期間は必要時に判断する。単一DBであり冗長化はない。バックアップ・復元確認を受入れに含める。[Volume](https://docs.railway.com/volumes/reference)

設定はUIで管理する。既存Config as Codeの廃止予定を踏まえ、新railway.tomlや新IaCは導入しない。[公式告知](https://docs.railway.com/config-as-code/reference)
